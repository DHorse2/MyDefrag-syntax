# Logging Text Inventory

> Generated by `npm run inventory:logger`.

## Scope

Scanned 70 production JavaScript files under `src` and `build`. Tests, generated
catalogs/reports, dependencies, comments, and commented-out calls were
excluded.

## Findings

- Active logger call sites: 189
- Literal fragments: 197
- Translatable literal occurrences: 181
- Unique translatable literals: 178
- Source characters: 8132
- Dynamic-only logger calls: 18

| Method | Calls | Translatable literals | Characters |
| --- | ---: | ---: | ---: |
| info | 24 | 32 | 1567 |
| warn | 6 | 6 | 408 |
| dbg | 133 | 130 | 5630 |
| err | 17 | 7 | 289 |
| message | 4 | 5 | 218 |
| messageDetail | 5 | 1 | 20 |

Debug logging is the largest portion: 130 strings and 5630 characters.
All non-debug logger levels together contain 51 strings and
2502 characters.

## DeepL estimate

The locale registry contains 17 non-English locales.
Translating every occurrence into every configured locale is an upper
bound of 138244 source characters. Exact-string deduplication lowers this
slightly to 136697.

The batched build path would need at most 17 translation requests.
The one-entry-at-a-time fallback path would need 3077 requests. Existing
translations and the live supported-language filter can reduce both totals.

## Boundaries

The primary count covers direct literals in `logger.*` calls. The 18
dynamic-only calls are listed in the detailed inventory but require a
separate data-flow review to count their possible runtime messages. Console
logging and startup diagnostics were measured by the scanner but excluded
from this logger-only estimate.

Detailed evidence: `build/language/reports/inventory/Logger-Strings.md`.
